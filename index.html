01 / FTSOv2

ライブ価格ボード

取引所やなくて、Flareのオラクル「FTSOv2」から直接取ってきた価格や。数秒ごとに勝手に更新されるで。

—

使っている機能FTSOv2（Flare Time Series Oracle）

FTSOv2は、Flareに組み込まれた分散型のオラクルや。約100のデータプロバイダが価格を出し合って、その結果がチェーン上に記録される。なかでも「ブロックレイテンシ・フィード」はブロックごと（1〜2秒ほど）に更新されて、読むだけやったら手数料もかからへん。

  • 呼んでいる関数：FtsoV2.getFeedsById(bytes21[])
  • コントラクト：取得中…（アドレスは公式のFlareContractRegistryから毎回取得）
  • 価格は「値 ÷ 10の小数桁数乗」で計算しとる（例：FLR/USDは小数8桁）

02 / FTSOv2

XRP ⇔ FLR 換算

「XRP 1,000枚は今何FLR？」みたいな計算が一発でできる。上の価格ボードと同じFTSOの価格を2つ割り算して出しとるで。

—
価格を読み込み中…

使っている機能FTSOv2 のクロスレート

FTSOの価格はどれも「○○/USD」やから、2つの価格を割り算したら別の組み合わせのレートが出せる。たとえばXRP→FLRは「XRP/USD ÷ FLR/USD」や。2つの価格は同じブロックで読んだもんを使うから、タイミングのずれもない。

  • 呼んでいる関数：FtsoV2.getFeedsById(bytes21[])（価格ボードと共通）
  • USDを選んだときは、FTSOの値をそのまま使う
  • 取引所で実際に交換するときの値段とは、手数料やスプレッドの分だけずれるで

03 / FTSO Scaling

価格の「証明」をチェック

FTSOは90秒ごとに、約100のプロバイダの答えから正式な価格（アンカー価格）を決める。その価格が本物かどうかを、証明データを使ってチェーン上で確かめるツールや。

FLR/USD・XRP/USD・BTC/USDの最新のアンカー価格を取ってきて、1つずつ検証するで。
フィードアンカー価格参加率証明の長さチェーンでの検証

使っている機能FTSO Scaling（アンカーフィード）とMerkle証明

90秒ごとの正式な価格は、全部まとめて「Merkleツリー」っていう形にして、その根っこ（Merkleルート）だけをチェーンに記録しとる。個々の価格は、Flareのデータ公開サーバー（DA Layer）から「証明」とセットで受け取れる。その証明をコントラクトに渡すと、記録済みのルートと計算が合うかどうかを確かめてくれるんや。1つでも数字を書き換えたら計算が合わんようになるから、改ざんされてへんことが分かる。

  • 証明の取得：DA Layer API の POST /api/v0/ftso/anchor-feeds-with-proof
  • 検証：FtsoV2.verifyFeedData(FeedDataWithProof)（読むだけやからタダ）
  • コントラクト：FtsoV2

使っている機能FAssets（FXRP）

FAssetsは、XRPみたいにスマートコントラクトがないチェーンの資産を、Flare上で1対1で使えるようにする仕組みや。「エージェント」が担保（ステーブルコインやFLR）を預けてミントを引き受けて、XRPの入金はFDC（Flare Data Connector）で証明される。最近は、預かったXRPを1か所にまとめる「コアボールト」もできて、少ない担保でたくさんミントできるようになったんや。

  • 発行量：FXRP.totalSupply()（トークンのアドレスは AssetManagerFXRP.fAsset() から取得）
  • エージェント：AssetManagerFXRP.getAvailableAgentsDetailedList(start, end)
  • コアボールト：AssetManagerFXRP.coreVaultAvailableAmount()
  • 1ロットの大きさ：AssetManagerFXRP.lotSize()
  • コントラクト：取得中…

使っている機能Flare Smart Accounts

XRPLのアドレスごとに、Flare上に専用の「パーソナルアカウント」が1つ決まっとる。XRPLで決まった宛先にメモ付きの送金をすると、FDCがその送金を証明して、パーソナルアカウントが中身の指示（FXRPのミントや送金、Firelightへの預け入れなど）を実行してくれるんや。アドレスは最初の指示より前から計算で決まっとるから、まだ使ってへんアドレスでも表示できるで。

  • アカウントの住所：MasterAccountController.getPersonalAccount(string xrplOwner)
  • 使い始めたかどうか：そのアドレスにコントラクトのコードがあるか（eth_getCode）
  • 残高：FXRP、stXRP（Firelightのボールト）、FLR、WFLRの balanceOf

06 / Secure Random Number

Flare乱数で抽選

プレゼント企画やミートアップの抽選に。誰にも操作できへんFlareの乱数で当選者を決めて、あとから誰でも結果を検証できるで。

0人が参加。重複した名前は1人として数えるで。乱数は約90秒ごとに新しくなるから、同じ90秒の間に引き直しても結果は変わらへん。
ここに当選者が出るで

使っている機能Secure Random Number（セキュア乱数）

Flareでは、FTSOのデータプロバイダが価格を出すときの「コミット・リビール」の仕組みから、約90秒ごとに256ビットの乱数が生まれる。全員が答えを公開するまで誰にも結果が分からへんから、1人のプロバイダが操作することはできへんのや。

  • 呼んでいる関数：RandomNumberV2.getRandomNumber()
  • コントラクト：取得中…
  • isSecureがfalse（どこかのプロバイダが答えを公開せんかった回）のときは、抽選せえへん設定にしとる
  • 当選者の決め方：参加者リストから、keccak256(abi.encode(乱数, i)) mod 残り人数番目の人を1人ずつ選ぶ。乱数と参加者リストがあれば、誰でも同じ結果を再現できる

使っている機能WNat（WFLR）と RewardManager

FLRは「WFLR」にラップすると、FTSOのデータプロバイダに委任できる。委任したWFLRはプロバイダの投票力になって、プロバイダの成績に応じた報酬が委任した人にも配られるんや（WFLRは自分のウォレットから動かへん）。

  • 残高：eth_getBalance と WNat.balanceOf(address)
  • 委任先：WNat.delegatesOf(address)（割合はbips、10000＝100%）
  • 未請求の報酬：RewardManager.getStateOfRewards(address)。報酬はだいたい25エポック（約3か月）で期限切れになるで
  • コントラクト：WNat / RewardManager
  • プロバイダの名前はチェーン上にはないから、ウォレットが使うコミュニティのリストから載せとる

使っている機能Flareのコンセンサスと Flare Systems Protocol

Flareのブロックは、Avalanche由来の「Snowman++」っていう合意の仕組みで作られて、1秒ちょっとで確定する。その上で「Flare Systems Protocol（FSP）」が時間を区切っとって、90秒ごとの「投票ラウンド」でFTSOのアンカー価格やFDCの証明、乱数が決まる。約3.5日ごとの「報酬エポック」の区切りで、プロバイダの顔ぶれや委任の重みが更新されて、報酬が計算されるんや。

  • ブロック・ガス代：eth_getBlockByNumber（baseFeePerGas）
  • 送金手数料の目安：21,000ガス × 基本ガス代（ドルはFTSOのFLR価格で換算）
  • ラウンドとエポック：FlareSystemsManager.getCurrentVotingEpochId()、getCurrentRewardEpochId()、currentRewardEpochExpectedEndTs()
  • コントラクト：取得中…

09 / Flare MCP Server

AIにFlareをつなぐ

Flare公式の「MCPサーバー」をAIに追加したら、話しかけるだけでFlareのチェーンを調べてもらえる。設定はURLを1つ入れるだけ、APIキーもいらんで。

https://mcp.flare.network
つないだら、こんなふうに聞いてみてな
  • FLR/USDの今の価格は？
  • このアドレスの委任状況と未請求の報酬を見て 0x…
  • FXRPの今の発行量とエージェントの数は？
  • このトランザクションが失敗した理由を教えて 0x…
  • 今投票中のFIPを日本語でまとめて

できること・できへんこと

  • できる：FTSOの価格、FDC、FAssets（FXRP）、Smart Accounts、委任と報酬、ガバナンス提案、トランザクションの中身、公式ドキュメントの検索
  • できへん：署名と送信。MCPサーバーは読み取り専用で、取引は「未署名のトランザクション」を作るところまでや。実行するときは、中身をよう確認してから自分のウォレットでやってな
  • 注意：秘密鍵やシードフレーズは、AIにも絶対に教えたらあかん。AIの答えが間違うこともあるから、大事なことは公式の情報でも確かめてな
AIごとの追加方法 （2026年11月時点。画面の名前は変わることがあるで）
ClaudeWeb・アプリ
  1. ブラウザで claude.ai を開いて、設定 → コネクタ に進む
  2. 「コネクタ」の横の ＋ を押して、カスタムコネクタを追加 を選ぶ
  3. 名前に Flare、URLに https://mcp.flare.network を入れて 追加
  4. Webで追加したら、iPhoneやAndroidのClaudeアプリでも使えるようになる

無料プランはカスタムコネクタが1つまで。スマホのアプリから直接追加する機能はまだベータ版やから、Webでやるのが確実や。

Claude公式ヘルプ ↗
ChatGPTWeb
  1. ブラウザで chatgpt.com/plugins を開く
  2. ＋ を押して、Add custom MCP server を選ぶ
  3. 名前に Flare、Server URLに https://mcp.flare.network を入れる。認証は No authentication を選ぶ
  4. 注意書きを読んで I understand and want to continue、つぎに Create as a plugin を押す
  5. プラグインをインストールしたら、チャット欄で @ を打って Flare を選んで質問する

追加はWeb版から。プランや時期によって画面が違うことがあって、少し前までは「設定 → コネクタ → 詳細設定 → 開発者モード」から追加する形やった。有料プランが必要な場合もあるで。

Muse（Meta）チャットで頼む
  1. Museには「MCPサーバーを追加する」設定画面がないから、チャットで頼む形になる
  2. 新しいチャットで、たとえばこう送る：
    https://mcp.flare.network のMCPサーバーに、カスタムコネクタでつないでほしい。認証は不要です。
  3. Museが接続を作ってくれるから、出てきたカードの Connect を押す

使っている機能Flare MCP Server

MCP（Model Context Protocol）は、AIが外部のデータや道具を使うための共通ルールや。Flareが公式に用意したMCPサーバーを通すと、AIがFlareのコントラクトを直接読んだり、Developer Hubのドキュメントを調べたりできる。どのAIでも、同じURLを1つ入れるだけでつながるのがええところや。
